# Section 2: Related Work

## 2.1 OCR and Vision-Language Models for Document Parsing

The field of document OCR has undergone a fundamental shift over the past several years, moving from multi-stage pipeline architectures—where text detection, segmentation, and recognition are handled by separate components—toward unified, end-to-end vision-language models (VLMs) that treat document parsing as a single sequence generation task.

**GOT-OCR 2.0** (Wei et al., arXiv:2409.01704, 2024) exemplifies this trend with a 580M-parameter model that handles a wide range of "characters"—plain text, mathematical formulas, tables, charts, sheet music, and geometric shapes—through a single high-compression encoder and long-context decoder, producing output in Markdown or LaTeX. **olmOCR** (Poznanski et al., arXiv:2502.18443, 2025) and its successor **olmOCR 2** (arXiv:2510.19817, 2025) take a complementary approach, training Qwen2.5-VL-7B with reinforcement learning from verifiable rewards (RLVR) on unit-test-based feedback, achieving state-of-the-art results on the olmOCR-Bench across table parsing, multi-column layouts, and mathematical formula conversion. **PaddleOCR-VL** (Cui et al., arXiv:2510.14528, 2025) offers a 0.9B ultra-compact VLM from Baidu targeting multilingual document parsing with coverage of text, tables, formulas, and complex layouts. **Mistral OCR** (Mistral AI, 2025) is a proprietary API that claims state-of-the-art accuracy on tables and handwriting in commercial benchmarks.

Our baseline model, **HunyuanOCR** (Tencent Hunyuan Vision Team, arXiv:2511.19575, 2025), represents one of the leading open-weight OCR VLMs, achieving strong performance on text spotting, document parsing, and structured information extraction. It employs a native-resolution ViT encoder (0.4B parameters) coupled with a lightweight LLM (Hunyuan-0.5B), trained end-to-end with reinforcement learning.

A critical limitation shared by all of these systems is that their output representations are confined to clean text, Markdown, and structural HTML: **none of them preserve text formatting attributes**. Strikethrough annotations, underline markers, and semantic text color are silently discarded at inference time. This is not an implementation detail but a fundamental gap in the output vocabulary of these models—no training data, evaluation benchmark, or output format standard currently exists to support these features. The present work addresses this gap directly.

## 2.2 Document Understanding Benchmarks

Benchmark design has played a central role in advancing document understanding. **OmniDocBench** (Ouyang et al., arXiv:2412.07626, CVPR 2025) is currently the most comprehensive open benchmark for PDF document parsing, covering 1,355 pages across 9 document types, 4 layout types, and 3 languages. Its annotation schema defines 15 block-level categories (including title, paragraph, table, figure, equation, header, and footer) and 4 span-level categories: `text_span`, `equation_inline`, `equation_ignore`, and `footnote_mark`. Notably, this exhaustive schema contains no annotation type for strikethrough, underline, or text color—confirming that formatting-aware evaluation is entirely outside the scope of the most comprehensive existing benchmark.

**DocBank** (Li et al., 2020) and **DocLayNet** (Pfitzmann et al., 2022) are large-scale document layout analysis datasets covering academic papers and business documents respectively; neither annotates text formatting attributes. For financial-domain tables specifically, **FinTabNet.c** (Smock et al., ICDAR 2023) provides 2,064 curated table annotation pairs from the original FinTabNet dataset, which we use to evaluate baseline table recognition performance. **PubTables-1M** (Smock et al., arXiv:2110.00061, CVPR 2022) offers approximately one million scientific table images spanning detection, structure recognition, and functional analysis tasks—establishing the scale and methodology for large-scale table benchmarking, though it covers scientific rather than financial documents. **SynFinTabs** (Bradley et al., arXiv:2412.04262, 2024) provides 100,000 synthetic financial table images with HTML, JSON, and CSV annotations; we use a subset for both training and evaluation.

Our held-out evaluation set of 200 annotated pages is, to our knowledge, the first benchmark to include human-verified annotations for strikethrough, underline, colored text, and complex financial table structure in a single unified schema. It fills the gap that OmniDocBench and all prior benchmarks leave open.

## 2.3 Financial Table Recognition

Financial tables present distinct challenges beyond those found in scientific or general document tables: they routinely feature multi-level column headers spanning merged cells, row groups with implicit hierarchical structure, and mixed numeric-textual content under compact typographic conventions. Recognizing the difficulty of this domain, **FinTabNet** (Zheng et al., WACV 2021) introduced a large dataset of financial table images drawn from Fortune 500 earnings reports, with cell-level structural annotations derived by matching PDF source to HTML structure. Its curated successor, **FinTabNet.c** (Smock et al., ICDAR 2023), corrected annotation inconsistencies and established a more reliable evaluation protocol.

**SynFinTabs** (Bradley et al., 2024) demonstrated that synthetic generation can produce financial table images at scale with faithful structural annotations, enabling data-hungry model training without manual annotation effort. Most recently, **Tan et al.** (arXiv:2508.05669, 2025) showed that fine-tuning Qwen2.5-VL-7B with standard LoRA on a curated set of 2,152 image-text pairs from Malaysian audited financial reports achieves 96.53% TEDS—surpassing GPT-4o and Gemini 2.5 Flash on that single-source dataset. This is the closest prior work to our table recognition contribution: it demonstrates that domain-specific VLM fine-tuning is highly effective for financial tables.

However, all existing financial table work is single-feature: none of these papers address strikethrough, underline, or colored text, and none construct a multi-source training set spanning real SEC filings, synthetic data, and diverse annotation features. Our EDGAR pipeline contributes real-world financial table pairs extracted directly from public filings, complementing synthetic sources with authentic typographic variation.

## 2.4 Parameter-Efficient Fine-Tuning

Fine-tuning large pre-trained models for downstream tasks is made practical by parameter-efficient fine-tuning (PEFT) methods, of which **LoRA** (Hu et al., arXiv:2106.09685, ICLR 2022) is the most widely adopted. LoRA freezes pre-trained weights and injects trainable low-rank decomposition matrices $\Delta W = BA$ at each target layer, reducing trainable parameters by up to four orders of magnitude relative to full fine-tuning while matching or exceeding its downstream performance on language modeling tasks. Standard LoRA is our ablation baseline.

**QLoRA** (Dettmers et al., arXiv:2305.14314, NeurIPS 2023) extends LoRA to 4-bit quantized models via a new NF4 data type and double quantization, enabling fine-tuning of 65B-parameter models on a single 48GB GPU. **DoRA** (Liu et al., arXiv:2402.09353, ICML 2024 Oral) decomposes the *pre-trained weight* $W_0$ into magnitude (column norms) and direction (unit vectors) components, applying LoRA to directional updates and achieving consistent improvements over LoRA on LLaMA, LLaVA, and VL-BART.

Our proposed method builds on **Dual LoRA** (Xu et al., arXiv:2512.03402, 2025), which instead decomposes the *weight update* $\Delta W$ into two groups: a magnitude group $W_m = \operatorname{ReLU}(BA)$ controlling the scale of each parameter update, and a direction group $W_d = \operatorname{Sign}(DC)$ controlling its sign. The final update is $\Delta W = \frac{\alpha}{\sqrt{r_1 r_2}} W_m \odot W_d$, where $\odot$ denotes the Hadamard product. This decomposition allows the model to selectively activate updates (via the ReLU gate) and independently control their direction (via the Sign binarization with straight-through estimator gradients), achieving higher effective rank in $\Delta W$ than standard LoRA at the same parameter budget. Dual LoRA has been evaluated exclusively on NLP tasks—natural language understanding and commonsense reasoning with RoBERTa, DeBERTa, and LLaMA families—and has never been applied to vision-language models or document OCR. We are the first to do so.

## 2.5 Formatting-Aware Document Recognition

The recognition of text formatting attributes—strikethrough, underline, and semantic color—has received almost no attention in the modern document understanding literature.

For strikethrough, the sole prior work is **Adak and Chaudhuri** (IEEE ICFHR 2014), who proposed a binary classifier to identify struck-out words in *unconstrained offline handwritten* document images, motivated by the observation that struck-out text fed to an OCR engine produces garbage output. This work operates on handwritten manuscripts using classical image processing features and outputs only a binary detection decision—it neither recognizes the content of struck-out text nor addresses printed or financial documents. **Poddar et al.** (ICDAR 2021 Workshops, LNCS 12917, pp. 98–112) extended this to stroke-level localization in handwritten historical manuscripts, again in a non-OCR, non-financial setting.

For text color, **Hase et al.** (IJDAR, vol. 6, pp. 271–284, 2003) explored color channel segmentation to improve character extraction accuracy in color document images—a pre-deep-learning approach that treats color as a nuisance variable for improving recognition accuracy, not as semantic information to be output. No modern work outputs text color as part of an OCR recognition result.

For underlined text, we found no prior work specifically targeting underline detection or recognition as an OCR output feature.

These three bodies of prior work share three disqualifying limitations relative to our task: they target handwritten or generic document settings (not financial), they use classical rather than VLM-based methods, and none produces the formatted output representation we require (`~~text~~`, `<u>text</u>`, `<span style="color:NAME;">text</span>`).

**In aggregate**, no existing work addresses the combination of strikethrough, underline, colored text, and complex financial table recognition in a single model or dataset. The closest individual contributions—Tan et al. (2025) for financial tables, Adak and Chaudhuri (2014) for strikethrough—each cover exactly one of our four target features and fail to generalize to the others. OmniDocBench (CVPR 2025), the most comprehensive document parsing benchmark, contains no evaluation protocol for any of the three formatting features. We address all four simultaneously with a unified dataset, model, and evaluation benchmark.
